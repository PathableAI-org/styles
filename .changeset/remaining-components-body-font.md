Render body text in the app shell, feedback, form, marketing and workflow components in Nunito, the brand body typeface, without a page-level font. `pathable-app-shell`, `pathable-bottom-navigation`, `pathable-site-alert`, `pathable-empty-state`, `pathable-loading`, `pathable-page-error`, `pathable-toast`, `pathable-error-message`, `pathable-optional-form-section`, `pathable-segmented-control`, `pathable-bento-tile`, `pathable-chip-rail`, `pathable-screenshot-frame`, `pathable-workflow-panel` and `pathable-wizard` now set `font-family: var(--pathable-font-body)` on their root, and the toast dismiss and action controls inherit it. Before, text these components left to inherit fell back to the browser's default serif font, and the toast dismiss button to the user agent's button font, when the page set none. `pathable-accordion`, `pathable-banner` and `pathable-modal` already rendered in Nunito through the USWDS rules they extend; their roots now take the typeface from `--pathable-font-body`, and the accordion and banner buttons inherit it and the modal close button sets it, where they used to render in the user agent's button font. `pathable-wizard__heading` and `pathable-wizard__section` are headings, so they now render in Fredoka, the brand heading typeface, not in the fallback font. They keep their bold weight, as the wizard page documents, so the browser synthesises bold from Fredoka Regular, the only weight the package ships. Headings that set their own typeface keep it. Text that asks for `font-weight: 700` in these components, such as the selected segmented control option, the active navigation items and the accordion button labels, now renders in Nunito SemiBold, because the package ships only Nunito 400 and 600; before, it rendered bold in the fallback font. Text widths and line heights shift slightly because Nunito's metrics differ from the fallback fonts.
